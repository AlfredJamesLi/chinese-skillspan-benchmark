前言与使用说明

本手册用于Chinese SkillSpan中文招聘文本的胜任力跨度标注，供编码员、复核人员及使用本数据集的研究者查阅。标注任务是从原文中识别应聘者所需的语言能力（L）、知识（K）、职业技能（S）和通用能力（T），记录相应片段及类型。手册说明标注范围、边界选择、类型判断和疑难处理，并提供案例供对照。

概念来源与标注原则

四类标签以欧洲技能、能力、资格和职业分类（ESCO）及欧洲资格框架（EQF）为概念参照，具体规则结合中文招聘表达制定。[ESCO14] [EQF] 学历归入K、明确行业背景中的领域名归入广义K，以及工具按语境区分K或S，均包含本项目约定。中文实体的具体边界与类型以本手册的操作性定义为准。

每个实体须取自原文中的连续片段，在完整表达要求的前提下尽量简短，不改写、不补词。最终标注采用单层、不重叠结构。同名词可能因语境不同而属于不同类型，不能仅凭“熟悉”“掌握”等引导词判类。本版按作者确认与论文已有明确答案对齐；没有明确答案的议题仍保留待决。此次文档修订不代表此前编码员使用了本修订文件。

阅读与查阅方法

首次使用时，建议先阅读四类定义，再学习范围与边界规则。实际编码依次判断“是否属于标注范围”“选择哪段原文”“属于哪类”；遇到歧义时查阅对应案例，仍不能确定的提交复核。

“跨度”（span）指选中的连续原文，“边界”指其起止位置。“确认空标注”表示检查后确定没有目标实体；“未决”表示证据不足或仍有争议，两者须分开记录。“暂记S”仅用于规定条件下的类型复核，不是最终标签，不能直接用于训练。

正文中的R08–R23为规则增补编号；附录A的EX001–EX124为案例查阅编号。“旧案例128”等号码沿用历史记录标识。案例用于解释规则与裁决理由，其数量按查阅条目统计，与独立评测样本数分开记录。方括号内的文献键对应文末参考文献；[本协议]表示项目规则。

版本与复现约定

复现时应分别记录手册、提示词、数据及评测协议的实际版本，不能根据当前手册推定历史调用所用规则。人工参考标签与Silver-plus教师监督标签承担不同用途，后者不会因人工抽查而自动成为人工参考标签。已发布或冻结的数据须保留原版本；后续调整应另存版本并记录差异。历史执行信息及维护文件见附录B。

标签 ESCO 概念参照   本项目操作化 二类投影仅供评测 

对应案例：EX001—EX004（见附录A）

依据层级： ESCO / EQF 提供概念参照，本项目将中文招聘提及操作化为 K / L / S / T。学历和非语言资格映射 K、明确行业经验的领域名映射广义 K、工具按使用语境映射 S，均是本协议规则，不等于 ESCO 概念库逐项标签。[ESCO14] [EQF] [本协议]

SkillSpan [Z22]提供跨度选择、知识／技能标注实例与二类评测的参照；本项目的四类定义见下表。

K

本协议: K

ESCO 门户支: Knowledge

权威定义（ESCO / EQF 原文）：“Knowledge means the outcome of the assimilation of information through learning. Knowledge is the body of facts, principles, theories and practices that is related to a field of work or study.” 编码时可理解为某个领域的事实、原理、理论和知识体系；不能只看有没有动词就决定是否为K。[EQF] [ESCO14]

中文招聘操作: 领域事实/原则/理论；明确行业背景/经验中的领域核心名（本项目广义 K）；学历与非语言职业认证的名称（资格柱无单独标签，映射到 K）

例: 本科及以上学历、计算机专业、ISO 27001、PMP

投影 [Z22]: → KNOWLEDGE

S

本协议: S

ESCO 门户支: Skills

权威定义（ESCO / EQF 原文）: “Skill means the ability to apply knowledge and use know-how to complete tasks and solve problems.”

中文招聘操作: 对知识的运用：工具、方法、可执行职业动作

例: 维护、测试、接口对接、岗位运用中的 shell

投影 [Z22]: → SKILL

T

本协议: T

ESCO 门户支: Transversal skills

概念定义：T是可用于多种工作、学习或生活情境的通用能力与特质，例如沟通、协作、自我管理。ESCO的社会与沟通类别包含communicating和leading others；report facts归在T4.1。T4.1是ESCO的细分类编号，本项目编码只填写T。[ESCO-T]

中文招聘操作：通用沟通、协作、自我管理和相关特质按T判断，即使这些能力写在岗位职责中，也不会仅因所在位置而变为S。

例: 沟通能力、沟通管理、客户汇报、责任心

投影 [Z22]: → SKILL

L

本协议: L

ESCO 门户支: Language skills and knowledge

权威定义（ESCO / EQF 原文）: ESCO 技能柱独立第四支（层级字母 L），与 Knowledge / Skills / Transversal 并列，不并进 K 或 S。支内：语种名是 knowledge concept，听说读写/CEFR 是 skill。

中文招聘操作: 语种、水平、语言考试/证书整段留在 L

例：英语、英语六级、CET-6、日语N2、英文阅读能力。英语六级和CET-6是资格名称的不同写法，均为L；仍按原文标注，不改写名称。这里的语言指自然语言，不包括Java、Python等编程语言。

投影 [Z22]: → KNOWLEDGE

概念参照链接（中文边界与类型按本手册操作规则判断）：

技能柱四支：skill_main (https://esco.ec.europa.eu/en/classification/skill_main) · Skills pillar (https://esco.ec.europa.eu/en/about-esco/escopedia/escopedia/skills-pillar) [ESCO-L] [ESCO14]

Knowledge：escopedia/knowledge (https://esco.ec.europa.eu/en/about-esco/escopedia/escopedia/knowledge) [EQF]

Skill：escopedia/skill (https://esco.ec.europa.eu/en/about-esco/escopedia/escopedia/skill) [EQF]

Transversal / report facts：TSC 2022 (https://esco.ec.europa.eu/en/about-esco/publications/publication/towards-structured-and-consistent-terminology-transversal) · report facts (https://esco.ec.europa.eu/en/classification/skills?uri=http://data.europa.eu/esco/skill/be6ab363-3de1-427f-a8ef-85d5b0250822) [ESCO-T]

Qualification（无 Q 标签，名称→K）：qualifications (https://esco.ec.europa.eu/en/classification/qualifications) “the formal outcome of an assessment and validation process…” [ESCO-Q]

人工标注始终保留L、K、S、T四类。为与二类方案对照，评测时可以另行合并标签；合并后的结果不得写回人工标注层。学历和资格在本项目中归入K，不意味着ESCO原本只有这四类。[ESCO14] [Z22] [本协议]

冲突处理：依次判断范围、边界和类型

对应案例：EX005（见附录A）

实体类型依据当前语境和四类操作性定义确定，四类标签之间不设固定优先顺序。遇到歧义时，先确认标注范围和实体边界，再比较候选类型；仍无法确定的，提交复核。[ESCO14] [ESCO-L] [ESCO-T]

SkillSpan的知识／技能标注实例可辅助理解；中文句子的具体判断按本手册的四类定义执行。[Z22] [本协议]

“范围”是这句话是否包含应聘者要求；“边界”是选中哪段原文；“类型”是选中的片段属于L、K、S还是T。三项依次判断，边界疑问在确定类型前处理。[AP08] [Kr95] [本协议]

最终标注采用单层、不重叠结构：一个原文字符最多属于一个实体，一个实体只保留一个最终类型。不在长实体内部再叠加短实体；其他解释另写入复核记录。[TKS02] [本协议]

操作：

对容易混淆的两类作针对性比较，例如K与S比较“知识内容还是职业运用”，S与T比较“具体职业职能还是通用能力”。[本协议]

边界有争议时，先看每个并列项在当前上下文中是否可独立表达原要求；可以则分开标。拆分会丢失必要动作、对象或限定时，保留最短的完整跨度。其他候选边界只记入复核记录，不同时放入最终标注。[本协议]

只有范围和边界已确定、但类型仍无法确定时，才可暂记S，并同时记录候选类型和adjudication_required（需要裁决）。这只是复核占位，不能当作最终S或直接作为训练标签。范围不清的记录不能用暂记S解决。[本协议]

学历与资格名   K

对应案例：EX006—EX008（见附录A）

本科及以上学历 / 大学本科及以上 / Bachelor Degree → K。[Z22] 附录 B.2.8 把 [Bachelor Degree] 标 KNOWLEDGE，专业名另条。

ESCO 把学历放在 Qualifications 柱，不是 skill；本协议无 Q 标签，资格名映射到 K。[ESCO-Q] [EQF]

学历资格本身按K标注；“5年以上”等工作年限不标。学历门槛与工作年限属于不同要求，不能混用排除规则。[Z22] [本协议]

“及以上／含以上”等学历门槛必须保留，例如标注“本科及以上学历”，不缩为“本科”。完整资格名的取法参考SkillSpan；中文门槛词的保留是本项目明确规则。[Z22] [本协议]

沟通与汇报：写在职责中也可以是T

对应案例：EX009—EX013（见附录A）

沟通能力、沟通管理、客户汇报、英语沟通 → T。[ESCO-T] [Z22] [Say18]

ESCO将report facts列入沟通类别T4.1，并标示为可跨情境使用的能力。T4.1仅用于说明概念来源，不是新增的标注标签。[ESCO-T]

SkillSpan没有单独的T标签，其SKILL类别不能直接等同于本项目的S。本项目把通用沟通和相关特质单列为T；仅在二类评测中再合并为SKILL。[Z22] [Say18] [本协议]

通用沟通写在“负责……工作”的职责句中，仍按T判断；具体技术操作另按S检验。[ESCO-T] [本协议]

职业技术动作仍是 S：接口对接、信息梳理（有具体业务对象）、处理问题+必要对象。人与人的联络协调不能仅凭「对接」二字判为 S；协调外部资源整段标 T，保留必要对象。[Z22] [本协议]

“能力”类表达：区分具体职业能力与通用能力

对应案例：EX014—EX017（见附录A）

区分S与T时，重点看能力是否依赖具体职业工具、方法或对象。沟通、学习及本手册规定的通用科研能力按T处理；具体职业能力按S检验。[ESCO-T] [ONET] [本协议]

1. 判断职业依赖：是否明确依赖某种工具、可执行方法或职业对象？若是，按S检验，例如编码能力、产品设计能力、数据分析能力。

2. 判断通用能力：是否主要表达通用认知、自我管理、沟通或人际能力？若是，按T检验，例如沟通能力、学习能力、沟通管理。仅“多个行业都会用”不足以判T；项目管理等具体职业职能仍需按R17判断。

3. 科研能力默认 为T（已裁）。仅当句中出现「论文 / 实验 / 课题」且强调研究方法 → S。[本协议]

网络 安全   ICT 一词三语境

对应案例：EX018—EX021（见附录A）

同一词语依据当前要求的内容和局部语境判类。[Nav09] [Z22] [本协议]

| 语境 | 标志 | 标 |

| --- | --- | --- |

| 学科 / 认证 / 专业名 | 前有专业 / 认证 / 学科 / 学历清单 | K。网络安全专业；认证里的”安全 / 网络” |

| 规划 / 运维 / 实施对象 | 文本明确要求规划、运维、管理、实施或集成网络／ICT系统，而不是仅介绍相关理论。 | S。规划网络及ICT……运维计划 → ”网络“” ICT 运维计划“ 各标 S |

| 泛化领域修饰 | 网络行业 / 安全领域 / ICT市场，无独立能力且未明确要求行业背景/经验 | 若仅为行业或市场修饰，不标；若明确要求候选人具备行业背景／经验，则按下节的背景规则判断。 |

“保证安全／确保安全”如果只表示目标或结果，不单独标为能力；含具体安全操作或资格名称时，另按实际内容判断，不因都出现“安全”就使用同一标签。

关键区分原则

对应案例：EX022—EX032（见附录A）

先区分“做什么”和“达到什么结果”。具体活动或方法可能是S；单独的效果、目标或业绩指标不标。动词可提供线索，但不是所有动词短语都属于技能。活动与结果的具体取舍以本项目规则为准。[Z22] [本协议]

「做什么」（动作 / 方法）→ 可能标 S

「达成什么」（结果 / 目标）→ 不标

| 片段 | 判定 | 处理 |

| --- | --- | --- |

| 分析推广效果 | 做什么（方法） | S |

| 制定有效的推广策略 | 做什么（方法） | S |

| 优化曝光与转化率 | 表达优化活动；若只留下“曝光”“转化率”，就变成两个指标名称，丢失了动作。 | 保留完整“优化曝光与转化率”为S，以保留优化动作及其对象。 |

| 保证流量/用户增长 | 达成什么（结果 / KPI） | 不标 |

| 确保渠道目标达成 | 达成什么 | 不标 |

“保证／确保”若只承诺结果，不单独标注；其后的内容仍要检查有无独立能力。“质量保证”作为职业活动名称时应整体判断，不能机械删除“保证”，详见R17。[PB05] [本协议]

| 后面是什么 | 处理 | 例 |

| --- | --- | --- |

| 纯结果 / 状态名词 | 整段不标 | 增长、流量、目标、业绩、稳定、质量、满意度、达标、合规、可靠、高效、优质；保证系统稳定；确保服务质量；保证安全 |

| 具体技术 / 方法对象 | 只标对象，不标「保证」 | 确保数据备份策略有效 → “数据备份”是待判断的候选内容；须有实际运用或知识语境才能确定S或K。本句示例本身不提供唯一类型。 |

| 动作 + 结果 | 只标动作 | 保证按SLA完成故障响应 → 故障响应 S |

「分析 / 制定 / 优化」后面的指标是做事对象，仍可标 S。不因前面有「保证」就默认全空或自动全标 S。

背景与经验：先判断要求内容，再决定是否保留“经验”

对应案例：EX033—EX037（见附录A）

本节取代v4.2.9中“通常删除经验”的笼统说法。“经验”是否保留，取决于删除后是否仍表达同一要求；工作年限和“优先”等条件本身仍不标。[本协议]

| 条件 | 处理 | 例 |

| --- | --- | --- |

| 只有泛化经历，无具体领域或活动 | 不标 | 工作经验、项目经验、丰富经验 |

| 明确要求行业背景/行业工作经验 | 领域核心名各标 K；经验、背景、年限和优先条件不单独标注。 | 有银行、咨询、服务行业工作经验优先考虑 → 银行 K、咨询 K、服务行业 K |

| 明确职业活动，剥经验后仍完整 | 职业活动按S；仅当删除“经验”不改变要求时，才把它留在实体之外。 | 大项目售前、数据分析、大数据开发、大数据项目实施、BI项目实施 |

| 特定职能/产品类型经历，剥经验只剩类别并改变原意 | 保留经验，整体 S | 产品经验、内容型产品经验 |

明确要求某行业背景时，将领域核心名标为广义K，是本项目借领域名表示背景知识的约定。先确认该表达是候选人的行业背景要求：公司宣传、岗位所在行业、市场修饰、纯兴趣和用户身份需与这类要求区分。“服务行业”保留“行业”，以明确领域含义。

口语“会……”：何时保留“会”

对应案例：EX038—EX040（见附录A）

招聘口语里「会」已经是本事本身 → 「会」进跨度，整段 T。[本协议]

「会」只表示「能做后面那件工具/职责」→ 仍剥「会」。SkillSpan 把态度标成 skill，并去掉冠词等功能词。[Z22]

| 原文 | 处理 |

| --- | --- |

| 会聊天、会说话、会来事、会做人 | 整段 T（含「会」） |

| 会使用Excel、会修电脑、会写SQL | 会使用Excel → Excel S；会修电脑 → 修电脑 S；会写SQL → 写SQL S。首例与论文附录A的G5对齐，其余保留职业动作。 |

「善于 / 熟悉 / 掌握 / 了解 / 精通 / 具备 / 有」仍只标后面的对象：善于与人沟通 → 与人沟通；有服务意识 → 服务意识。[Z22]（附录 B.3.6：advanced knowledge of / proficient in 是 trigger，不进跨度。）

跨度规则：原文连续、含义完整、尽量简短

对应案例：EX041—EX049（见附录A）

1. 从原文选择连续、完整的片段，不改拼写、不补词。例如“支持服”“操作系统的问”都是截断词语的错误边界。技术检查应满足sentence[start:end] == span，即按记录的位置截取原句，必须得到同一实体文本。[Z22] [D18] [AP08] [本协议]
