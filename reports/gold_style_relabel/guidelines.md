# Gold-style train relabel — 边界规范（Gold-length）

目的：把 **train 银标的碎跨度** 改写成与 **canonical Gold v2** 同一套边界，供后续编码器训练。  
80 条抽查已定稿（`sample80_final.json`，本轮不改）。规则扩标当前写入 `data/train_goldstyle_v3.jsonl` / `dev_goldstyle_v3.jsonl`（80 条人工锁定，其余 rule_v3）。**不改 Gold v2，不覆盖 `train.json`，不写论文数字。**

标签只允许：

| 类型 | 含义 | 例子 |
|---|---|---|
| L | 语言/语种 | 英语、普通话、英文读写能力 |
| K | 知识、学历、专业、证书、领域 | 医学专业、计算机相关专业、CET-6 |
| S | 可执行技能、方法、工具、经验活动 | 网络管理、维护和支持服务、Python |
| T | 软技能、特质、态度 | 沟通能力、责任心、职业道德 |

## 必须对齐 Gold 的边界（Gold-length 完整短语）

目标粒度 = **Gold 完整名词短语（complete NP）**，典型约 4–12 个 token（Gold 中位 4、均值约 5）。  
不是银标那种词中切断的碎片，也 **不是整段岗位职责 / 整句条款**。

1. **一条要求标成一个完整名词短语**，不要切成 2–4 字碎片，也不要把整段职责收成一条 S。  
   - Gold 典型：`沟通能力`、`虚拟化经验`、`英文读写能力`、`飞控计算机`  
   - Gold 完整 NP（少见长尾）：`多平台或关键应用程序的维护和支持服务`  
   - 不要：`维护和` + `支持服`（词中切断）  
   - 不要：把「负责…；协助…；完成…」整段职责标成一条 S
2. **不要从词中间切断**（禁止 `支持服`、`技术支`、`软件相`、`普通话表`）。补全到词/短语结束即可，遇到 `，。；、` 或「熟悉/掌握/了解/精通/具备/具有」就停，不要吃整句。
3. **只有不同要求才拆开**。同一 NP 里的并列修饰（维护和支持服务）包在一起；列出的多项独立技能（英语 / Python / 沟通能力）分开标。
4. **只标对候选人的能力要求**。不标：报名流程、公示、体检、资格审查手续、单位行政安排、免责声明、没有能力含义的套话。
5. **空句写死。** 整句没有能力要求 → `spans: []`。下列情况默认空，不要为了“有字”硬标：
   - **事业单位流程句**：报名/报考、资格审查/复审、笔试面试时间、准考证、体检、公示、本公告、咨询电话、请登录、岗位代码、招聘人数。
   - **福利/班次/行政**：五险一金、包吃住、班次、加班费、节日福利、公司提供的培训机会（不是岗位技能）、免责声明。
   - 只有工作地点或招聘人数、没有“熟悉/掌握/学历/专业/能力” → 空。
   - 提示列 `empty_hint` 只是规则提示，最终仍以本条为准；有明确能力短语时不要空。
6. 跨度必须是句中**连续原文**。类型只能是 L/K/S/T。不要改写句子，不要发明 ID。
7. 银标只给人看对照，**发给模型的第一轮不要带银标**，避免抄碎片。
8. **熟悉/掌握框架、语言、办公软件 → S**；学历、专业、资格考试、领域理论 → K。
9. **年限、形象外貌、身体健康、挑战高薪、留学优先、驾照（非司机岗）→ 不标。**
10. **禁止「岗位职责整段一条 S」。** 职责句里只标其中的完整技能短语；一句里多条独立技能就拆开。过长条款在约 12–14 token 处截断到最近的短语边界。
11. 公司给员工的培训/福利/班次/报名流程 → 空。

## 输出（给模型）

JSON 数组，每项：

```json
{"id": "1-s0000", "spans": [{"text": "完整名词短语", "type": "S"}], "comment": "一句理由"}
```

无技能：`"spans": []`。

## 输出（人工定稿写入时）

token 下标，左闭右开，与 `tokens` 对齐：`[[start, end, "S"], ...]`。  
大模型结果必须经人工 `accept` / `edit` / `empty` 后才能用于训练。
